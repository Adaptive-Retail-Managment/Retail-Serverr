# Decision register

Status vocabulary: **Accepted** (in the codebase now), **Provisional** (revisit at the stated
point), **Constrained** (fixed by the project brief).

| ID    | Decision                                                    | Status      | Rationale / implications                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----- | ----------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Modular monolith, single deployable API                     | Constrained | One NestJS process and one PostgreSQL database. Modules own their data; cross-module calls go through application services, never another module's repositories. No network boundaries to design around yet.                                                                                                                                                                                                                                                                    |
| D-002 | pnpm workspace monorepo (`apps/*`, `packages/*`)            | Constrained | Shared config and contracts without publishing packages. `PROJECT_STRUCTURE.md` assumes pnpm.                                                                                                                                                                                                                                                                                                                                                                                   |
| D-003 | pnpm **11.28.13**                                           | Accepted    | pnpm 12 is published as a Rust-native binary whose layout corepack 0.33 (bundled with Node 22) cannot launch (`bin/pnpm.cjs` missing). pnpm 11 is the newest line that works through corepack and `pnpm/action-setup`. Revisit when corepack supports pnpm 12.                                                                                                                                                                                                                  |
| D-004 | NestJS **11.2.11**                                          | Provisional | NestJS 12 is ESM-only (`"type": "module"`). The API is a CommonJS build tested with ts-jest + Jest 30, which cannot `require()` ESM packages on the project's Node 22 baseline. Nest 11 is the latest CommonJS line and matches the Node 22 target. Revisit together with an API-wide ESM migration (tsconfig `nodenext`, Jest ESM or a different runner) instead of mixing module systems.                                                                                     |
| D-005 | Prisma **6.19.3**                                           | Provisional | npm's `latest` tag currently points at Prisma 8.0.0-rc; Prisma 7 changes the generator/config model. 6.19 is the last stable line verified with commonjs Nest + Jest. Re-evaluate before the first domain migration. Using an RC or an unverified generator change would risk the whole schema slice.                                                                                                                                                                           |
| D-006 | TypeScript **5.9.3**                                        | Accepted    | ts-jest 29 and typescript-eslint 8 both support `<6.1`. TypeScript 7 (native compiler) is not yet supported by this test toolchain.                                                                                                                                                                                                                                                                                                                                             |
| D-007 | Jest + ts-jest for API; Vitest for web/desktop              | Accepted    | Jest is the Nest default and handles decorator metadata; Vitest shares Vite's transform pipeline for React.                                                                                                                                                                                                                                                                                                                                                                     |
| D-008 | React 19 + Vite 7 + `@vitejs/plugin-react` 5                | Accepted    | Plugin-react 6 requires Vite 8. Vite 7 is the latest line whose React plugin is stable with the rest of the toolchain.                                                                                                                                                                                                                                                                                                                                                          |
| D-009 | Electron 45, shell only                                     | Provisional | Loads the built web app or the Vite dev server; no second renderer. Packaging/installers deferred until OS targets and offline storage are decided.                                                                                                                                                                                                                                                                                                                             |
| D-010 | Probes at `/health` and `/ready`, business API under `/api` | Accepted    | Probe paths stay stable and unversioned for orchestrators. Readiness returns 503 with a JSON body; liveness never touches the database.                                                                                                                                                                                                                                                                                                                                         |
| D-011 | API boots without PostgreSQL and reports `degraded`         | Accepted    | Prisma connects lazily; boot-time DB crashes hide failures from probes. Readiness decides traffic eligibility. Consequence: SQL errors surface per request until the DB is back.                                                                                                                                                                                                                                                                                                |
| D-012 | No second DB role for migrations yet                        | Provisional | Development uses one owner role. Production migration/least-privilege roles are an operations task before deployment.                                                                                                                                                                                                                                                                                                                                                           |
| D-013 | Business-type differences via configuration                 | Constrained | Grocery, fashion, pharmacy and cosmetics share core modules; behaviour differences are data/config, not code forks. No implementation yet.                                                                                                                                                                                                                                                                                                                                      |
| D-014 | AI remains advisory                                         | Constrained | Any future recommendation service writes proposals; approval/execution requires authorized human workflow. No AI code in Phase 0.                                                                                                                                                                                                                                                                                                                                               |
| D-015 | Prisma schema lives in `apps/api/prisma`, not `database/`   | Accepted    | Deviation from `PROJECT_STRUCTURE.md`. Prisma resolves `prisma`/`@prisma/client` relative to the **schema directory** and generates into that resolved package. With the schema under `database/prisma`, it auto-installed packages at the repo root and generated a different pnpm copy than the one `apps/api` imports, so the API would ship an ungenerated client. Co-locating with the consumer removes that class of failure. `database/` remains for seeds and diagrams. |
